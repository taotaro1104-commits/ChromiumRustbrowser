# P0 プロトタイプ 実行計画(CEF 経由)

目的(設計書 §10 フェーズ0 / ゲート G1 の前段): CEF 上で起動し、タブ・履歴・ブックマーク・
セッション復元が動く最小のブラウザを作る。Chromium 本体のビルドは不要(CEF のビルド済み配布物を使う)。

## 方針
- 判断ロジックは M0 のクレートに置き、CEF はトレイト `WebContentsHost` の実装として差し込む。
  P1 で `chromium-ffi` に差し替えても `shell-core` 以上は変更しない。
- `unsafe` を許すのは CEF 連携クレート(`cef-host`)のみ。それ以外は従来どおり `forbid`。
- メモリ最小化: セッション復元は最後に開いていたタブだけを生成し、残りは Discarded 状態で保持する
  (アクティブ化した時点で `restore` が実体を作る)。

## リスク
- CEF 配布物のサイズ(数百 MB)とダウンロード。`cef` クレート(cef-rs)の `export-cef-dir` で共有配置する。
- CEF のウィンドウ/UI は Windows 実機での目視確認が必要。自動テストは `shell-core` までで担保する。
- P0 のメモリは CEF 由来の上乗せがあり、設計書の予算(150/250/600MB)は Content API 移行後(G2)で判定する。

### 実機で確認した内容
- `--url` 指定で起動し、タイトル `Example Domain - Rust Browser` が反映される(CEF → `shell-core` のイベント経路が動作)。
- ウィンドウを閉じると `history` に 1 件、`session` に 1 タブが保存され、プロセスが全て終了する。
- 再起動(`--url` なし)でタブが復元され、アドレスバーに `rust lang` + Enter で DuckDuckGo の検索結果に遷移する。

### 実機操作の確認(2026-10-26、Win32 のマウス入力で実クリック)
- ＋: 新規タブが開く。✔(修正後)
- タブ切替: タブ名のクリックで表示・アドレス・ウィンドウタイトルが切り替わる。✔
- ☆/★: クリックで ★ に変わる。✔
- ×: タブが閉じ、アプリは継続する。✔(修正後)
- 20 タブ後にウィンドウを閉じると、セッションに 20 タブ・active=19 が保存される。✔
- 実機で見つけて直した不具合:
  1. 2 つ目のタブが空白になる。CEF 156 の既定は Chrome スタイルで、1 ウィンドウに BrowserView を 1 つしか置けない
     (`Cannot add multiple Chrome style BrowserViews`)。`BrowserViewDelegate::browser_runtime_style` で Alloy スタイルにした。
  2. タブの × でアプリごと終了する。Views 上のブラウザに `close_browser` を呼ぶとウィンドウが閉じるため、
     ビューを外して参照を手放す方式に変更した。
- 見つかった課題: タブが 4 つを超えるとタブ列が溢れて右側が操作できない。→ 対応済み: タブ数に応じてラベルを縮め(22/14/8 文字)、1 行 4/5/6 個で折り返す(`tab_layout.rs`、単体テスト 2 件)。20 タブで全タブに届き、1 行目のタブ切替と最終行の × を実機で確認。
  幅はウィンドウ・DPI 依存のため、固定幅を超える環境では再調整が必要(P1 のネイティブ UI で置換予定)。

### UI の見た目(カジュアル化)
- 配色: ツールバー=淡いラベンダー、タブ列=薄い青紫、アクティブなタブ=青+白文字、＋=桃色、★ オン=黄色、×=淡い赤。
- タブにはホストごとに決まる色の四角(🟦🟧🟩🟪🟥🟨)を付け、サイトを見分けやすくした。ツールチップは日本語。
- 実機で分かった制約: Views の背景色・文字色は、ビューをウィンドウに載せて表示した後でないと反映されない
  (`add_styled` は親に追加してから塗り、ツールバーは表示後の `paint_toolbar` で塗る)。

### スタートページ
- 新規タブとホームは、内蔵のスタートページ(`assets/start.html`)を開く。127.0.0.1 の空きポートで `GET /` だけを返す
  最小サーバ(`start_page.rs`)で配る。核は `file:` / `data:` を拒否する方針のため、スキーマ判定は緩めず http で配信した。
- スタートページの URL は `Shell::set_internal_prefix` で履歴に記録しない(shell-core のテスト 1 件追加)。実機で履歴 0 件を確認。
- 起動できなかった場合は DuckDuckGo をホームにする。
- 将来は専用スキーム(`rustbrowser://`)で置き換える(P1)。

### レビュー指摘への対応(コードレビュー+セキュリティレビュー)
修正済み:
- UI 更新の予約フラグが再入で固まる(`sync_pending`)→ `Ctx` の外の thread_local にし、必ず戻す。再入で捨てた呼び出しはログに出す。
- スタートページサーバの 2 秒ブロック・接続占有 → ヘッダ終端までを総時間 2 秒で読み、接続ごとのスレッド(同時 8)、
  `Host` 検査(DNS rebinding)、CSP 等のヘッダ。テスト 5 件。
- 開けない URL(`file:` / `about:flags` 等)が黙って無視される → `ShellError::UnsupportedUrl`。`about:` は `about:blank` のみ許可。
- ページ起点の遷移がポリシーを通らない → `RequestHandler::on_before_browse` でメインフレームの遷移に同じ検査。復元時もポリシーを適用。
- ポップアップ連打 → ユーザー操作の無いものは開かない。タブ数の上限 200。
- 巨大なタイトル/URL → タイトル 1024 文字、URL 8192 バイトで制限。履歴にも適用。保存セッションは上限超過時に古いタブから落とす。
- `policy.json` が壊れていると既定で起動 → 存在して不正なら起動しない(fail-closed)。
- 復元に失敗した起動で古いセッションを上書き → その起動は自動保存を止める。
- スクロール位置の持ち越し(`pending_scroll`)、フォールバックホームが履歴から外れる問題、拒否された入力が欄に残る問題。

続けて対応した 3 件:
- **サンドボックス有効化**: CEF の `bootstrap.exe`(サンドボックス用ライブラリ内蔵)を `rustbrowser.exe` として置き、
  同名の `rustbrowser.dll`(このクレートの cdylib)の `RunWinMain` を呼ばせる構成にした。`sandbox_info` を
  `execute_process` / `initialize` に渡し、`no_sandbox` は 0 固定(無効化する設定は持たない)。`unsafe` は `RunWinMain` の
  C ABI 境界だけ。実機で、レンダラーが Untrusted(整合性レベル 0x0)、GPU が Low、ブラウザが Medium で動くことを確認。
- **再生中タブの保護**: `AudioHandler` の開始/停止を `Shell::set_audible`(`SetFlags`)に配線。再生中の非表示タブは 30 分経っても
  破棄されない(shell-core のテスト 2 件)。実機でローカルの音声ページを再生し、開始イベントが届くことを確認。
  再生音が実際に出ているか(キャプチャで消音されないか)は未確認なので、手元で聞いて確認すること。
- **ホスト操作の失敗時の巻き戻し**: `Store` が失敗した `Create` / `Restore` / `Navigate` を `Action::HostFailed` に変換して State を戻す。
  Create 失敗=タブを取り除き直前のタブへ、Restore 失敗=破棄状態へ(再選択で再試行)、Navigate 失敗=新 URL で作り直す。
  連鎖は 1 回の dispatch で 16 回まで。テスト 5 件(モックに操作別の失敗注入 `fail_ops` を追加)。

さらに対応した 3 件:
- **ページ状態の取得と復元**: ブラウザ側から JS を実行し、結果を `console.debug("__rb:<nonce>:<json>")` で受け取る
  (起動ごとの乱数 nonce で、ページからの偽装を防ぐ。受信は 96KB まで)。取得するのはスクロール位置・入力欄にフォーカスがあるか・
  テキスト入力の内容(パスワード・カード情報・`autocomplete=off` は対象外、種類は許可リスト方式)。30 秒ごとと、タブ切替の直前に取得。
  入力中のタブは破棄の対象から外れる。復元時は読込完了後にスクロールと入力内容を戻す(空の欄だけ)。
  実機で、スクロール 956 と入力内容が保存・復元され、パスワード欄は保存されないことを確認。
  WebRTC フラグは、カメラ/マイクの権限を許可する UI が無く(常に拒否)発生しないため、権限 UI を作る P2 で配線する。
- **URL の秘匿**: 履歴・ブックマーク・セッションに保存する URL から、ユーザー情報、`token` / `secret` / `password` 等を含むキーと
  `code` / `key` / `sig` / `sid` / `state` のクエリ、トークンを含むフラグメントを除く(`shell-core/src/redact.rs`、テスト 6 件)。
  表示中の URL は変えない。スタートページの URL はポートが毎回変わるため、セッションでは固定の印(`rustbrowser://home`)にして復元時に戻す。
- **破棄によるメモリ削減の実測**(debug ビルド、別サイトのタブ 19 枚。診断用に、プロファイル直下に `discard-now` を置くと
  メモリ圧迫時と同じ破棄を次の Tick で行う):
  | 状態 | プロセス | Private | Working set |
  |---|---|---|---|
  | 1 タブ | 7 | 224MB | 362MB |
  | 19 タブ | 25 | 809MB | 1,453MB |
  | 破棄の約 3 分後 | 9 | 459MB | 620MB |
  レンダラーは 1 つずつ約 10 秒おきに終了するため、効果が出るまで数分かかる。
- 実機で見つけて直した不具合: タブを閉じてもレンダラーが終了しなかった(参照を手放すだけでは実体が残る)。`close_browser` で閉じ、
  完了(`on_before_close`)までビューを親に残す。ウィンドウごと閉じようとされるため、その間の `can_close` は拒否する。
  また、日本語のタブ名が行からはみ出していたため、全角を 2 として幅で切り詰める。

未対応(P1 で扱う):
